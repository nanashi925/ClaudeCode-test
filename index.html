コーディング支援

// writing, editing, debugging

💻
コードを書く ▼
「○○な機能を作って」と伝えるだけ。関数、クラス、API、コンポーネント — 何でも生成します。

使い方の例

あなた: Express で JWT 認証のミドルウェアを作って
→ ファイルの作成・既存コードへの統合まで自動で行います
あなた: このAPIにページネーション機能を追加して
→ 既存のコードを読んでから、最適な方法で追加します
Tip: 具体的な要件を伝えるほど、正確なコードが生成されます。技術スタックやライブラリの指定も効果的。
🐛
デバッグ ▼
エラーメッセージを貼り付けるだけ。原因を特定し、修正を提案・実行します。

使い方の例

あなた: このエラーを直して：TypeError: Cannot read property 'map' of undefined
→ コードベースを調査し、根本原因を特定して修正します
あなた: テストが落ちてる原因を調べて
→ テストを実行し、失敗の原因を分析します
Tip: エラーメッセージと一緒に、何をしようとしていたかも伝えると、より的確な修正ができます。
🔄
リファクタリング ▼
コードの品質向上。命名の改善、関数の分割、設計パターンの適用など。

使い方の例

あなた: この関数を小さな関数に分割して
→ 責務を分析し、適切に分割します
あなた: このクラスの変数名をもっと分かりやすくして
→ 文脈を理解し、プロジェクト全体で一貫性のある命名に変更します
📚
コードの解説 ▼
初めてのプロジェクトでも大丈夫。どんなコードでも日本語で丁寧に説明します。

使い方の例

あなた: このプロジェクトの全体構造を教えて
→ ディレクトリ構成やアーキテクチャを分析して説明します
あなた: この正規表現が何をしているか教えて
→ パターンを分解して、一つずつ説明します

スラッシュコマンド & ショートカット

// quick actions at your fingertips

コマンド 説明
/help ヘルプとドキュメントを表示
/clear 会話をクリアしてリセット（コンテキストウィンドウの節約に）
/compact 会話を要約して圧縮（長い会話の途中で使うと効果的）
/commit 変更のステージング→コミットメッセージ生成→コミットを一発で
/review-pr プルリクエストのコードレビュー
/fast 高速モードの切り替え（同じOpusモデルで出力速度アップ）
Shift+Tab プランモードの切り替え（実装前に計画を立てる）
Esc 現在の生成を中断
\ 改行を入力（Enterで送信、\で改行）
@ファイル名 特定のファイルをコンテキストに追加

// maximize your Claude Max 5x plan

📝
CLAUDE.md を使う ▼
プロジェクトのルートにCLAUDE.mdを置くと、毎回読み込まれる「永続的な指示書」になります。

CLAUDE.md の例

# CLAUDE.md

## プロジェクト概要
このプロジェクトは React + TypeScript の SPA です。

## コーディング規約
- 関数コンポーネントのみ使用
- CSS Modules を使用
- テストは Vitest で書く

## よく使うコマンド
- テスト: npm test
- ビルド: npm run build
Tip: プロジェクト固有のルールや規約を書いておくと、私が一貫性のあるコードを書けるようになります。
🎯
効果的なプロンプト ▼
曖昧な指示より、具体的な指示。コンテキストを与えるほど良い結果が返ります。

良いプロンプトの例

❌ 曖昧
あなた: ログイン機能を作って
✅ 具体的
あなた: Express + Prisma で、メール/パスワードのログインAPIを作って。
JWTトークンを返して、refreshトークンもDBに保存する仕組みにして。
バリデーションは zod を使って。
Tip: 「技術スタック」「要件」「制約」の3つを伝えるだけで、出力品質が大幅に向上します。
♻
コンテキスト管理 ▼
長い会話はコンテキストウィンドウを消費。/compact と /clear を使い分けよう。

使い分けガイド

// 同じテーマで長く作業中 → /compact
// 会話を要約して圧縮、作業を継続できる

// 全く新しいタスクに移る → /clear
// クリーンな状態で新しい会話を開始
Tip: 5x プランなら大量のやり取りが可能ですが、長い会話より短く具体的なセッションの方が効率的です。
💪
権限モードの活用 ▼
安全性と効率性のバランス。許可設定を理解して最適化しよう。

権限について

// ファイルの読み取り → 自動的に許可
// ファイルの編集 → 設定次第で確認あり
// コマンド実行 → 安全なものは自動、危険なものは確認
// git push → 毎回確認（安全のため）
Tip: 信頼できるプロジェクトでは権限設定を緩和して、よりスムーズに作業できます。
